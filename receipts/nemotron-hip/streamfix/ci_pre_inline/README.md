# Published pre-inline CI audit

This snapshot audits all 22 published draft PRs 1082–1103 before the inline-source update. Every rollup is FAILURE. Each has exactly five reported check contexts: **desktop, mobile, zig and fmt SUCCESS; zig-windows FAILURE**. All 22 failed Windows job logs were fetched individually; each has the same unordered set of 28 distinct compiler error messages after normalizing generated struct/enum suffixes. This does not isolate one root cause.

GitHub tested actual PR merge refs into observed upstream main `d1018b318fb51981c4a18f12e40269a4d3ee9713`; it did not execute only the raw PR head. The passing checks are real partial integration build evidence for those old source combinations. Historical body wording that no integrated tree had been built is overtaken by this CI evidence. Windows qualification and GPU/model qualification of the actual upstream integration remain pending. New inline heads require their own new CI/check readback; this snapshot does not claim their checks passed.

One common diagnostic is `zig/src/core/digest_key.zig:34:42: expected type 'u128', found 'i64'`, pointing at `.inode = s.inode`, not timestamp conversion. The file's Git blob is identical at tested base76, observed upstreamd101 and all 22 old PR heads: `966f1fd2234e139d17b90f66e480226f595e2d47`. That proves an error in an unchanged file, **not that baseline Windows CI fails**: imports/instantiation and the merge tree may affect compilation. Exact-head workflow history for base76 and d101 returned only successful App/mobile push runs, with no Windows baseline evidence. Inherited failure is unproven.

The logs also show dynamic-library, Windows socket/handle/ABI and unsupported-platform diagnostics. No toolchain pin, check suppression, source fix, CI rerun or source publication was performed. This remains a real pending Windows CI issue.

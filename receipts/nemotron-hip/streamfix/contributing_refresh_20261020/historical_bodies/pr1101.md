## What this changes

Family code only: `zig/src/families/nemotron/hip/` and `zig/tests/nemotron_hip/gen.zig`. Each commit fuses launches of Nemotron's HIP decode on the shared kernels of [fork #39][f39] to [fork #43][f43]:

- 8caabbc4: the attention's q, k and v run as one grouped stream-tile launch (`ops.projectGroup`). A column's sum order depends on K alone, so the bits are those of three launches. A prompt pass keeps its three launches.
- b5de55c8: every block's residual add and the next block's input norm run as one launch (`hip.reduce.residualNorm`), the final norm after the last block too, and the MTP head's norms after its attention and MoE.
- 629c91d5: on one rank, a MoE block's expert rows, weights and shared row go straight to the residual's launch (`residualMoeRms`), so `tf_nemo_combine` and `tf_add` run inside it. Under tensor parallelism the ranks' fp32 shares are summed first, as before.
- 59789d65: a lane round runs a stream's Mamba rows through `ops.mambaWindow`: three launches for the window instead of four a row. Each row's state but the last goes to its snapshot slot from inside the kernels, so no state copy runs. Slot 0, the state before the window, is no longer kept: a keep holds the pending row at least (`keepRows` now refuses zero rows), so nothing read it. The test tool's rollback check runs for windows of three rows or more.
- b86e111b: Nemotron's attention has no RoPE, so q and the keys go to the planned walk as they are and its rows come back in the activation type: three casts fewer an attention layer.

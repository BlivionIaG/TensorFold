## What this changes

- `tf_add_rms` adds a row to the residual and norms the new row in one launch. It adds as `tf_add` does: an activation row, an fp32 rank sum as `tf_add_wide` does, or a MoE layer's expert rows summed as `tf_nemo_combine` sums them. Then it norms the row as `tf_rms` does.
- One block of 1024 threads takes a row. Each element's arithmetic is the replaced launches'. The norm's sum keeps `rms_kernel`'s order: one wave, lane l over the elements l, l + 32, ..., then the same xor tree. So the bits are those of the launches it replaces.
- `ops.residualRms` and `residualMoeRms` take it for rows of 1,025 to 8,192 values while the merged launches are on. Otherwise they run the launches it replaces. `reduce.residualNorm` sums the ranks' shares first, as `residual` does.
- `moe_nemotron.expertRows` returns a layer's expert rows, weights and shared row before their sum. `run` sums them as before, so a caller of `run` gets the same launches.
- No family calls the new op in this PR. [fork #44][f44] uses it.

Shared code: `ops/act.hip`, `launches/norms.zig`, `ops/norms.zig`, `reduce.zig`, `moe_nemotron.zig`, `launches.zig`, `ops/ops.zig`. No Qwen3.5 or Flash Next path calls the new kernel.

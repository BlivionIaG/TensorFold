## What this changes

- `tf_plan_attend_f16` and `_bf16` walk one row's query head over its keys in one block of 1,024 threads. They read q and write the row in the activation type, as [fork #42][f42]'s walk does.
- The block runs the four launches' code in turn: `plan_score_body`'s scores (a wave a key), `tf_softmax_stats`' max and sum on the first 256 threads, `plan_apply_body`'s 128-key tiles eight at a time, and `tf_sum_partials`' sum of the tiles in order. Each sum keeps its kernel's order, so the bits are those of the four launches.
- `ops.causalAct` takes it for spans up to 4,096 keys and heads up to 128 wide while the merged launches are on. Longer spans keep the four launches.
- Nemotron's decode takes it through `causalAct` ([fork #44][f44]). No family file changes.

Shared code: `decode/plan.hip`, `launches/plan.zig`, `ops/plan.zig`, `launches.zig`. Only Nemotron calls `causalAct`. Qwen3.5 and Flash Next do not.
